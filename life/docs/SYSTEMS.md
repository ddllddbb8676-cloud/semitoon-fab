# 세미툰 라이프 — 시스템 설계 (SYSTEMS)

구현할 수 있는 규칙과 숫자를 모은 문서입니다. 이름(키·id)은 `SPEC.md`를 따르고, SPEC에 없는 키는 맨 끝 **17. SPEC 추가 제안**에만 적었습니다.

- 돈 액수(연봉, 생활비, 집값, 주가, 대출)는 경제 설계(`ECONOMY.md`, `economy_history.json`) 담당입니다. 여기서는 **경제 모듈에 넘기는 입력값**만 정합니다 (5.10, 15장).
- 2027년 이후 시황과 R&D 스킬트리는 미래 설계(`FUTURE.md`, `future_tech.json`) 담당입니다. 여기서는 그 결과를 받는 자리만 둡니다 (5.11, 6.2).
- 진학률·기대수명·병역 기간·혼인 연령·출산율·정년 같은 현실 수치는 모두 **대략값**이고 게임용으로 다듬었습니다. 최종 숫자는 `life/tools/` 시뮬레이션(14장)으로 맞춥니다.
- 표기: `m(s,y)` = 분야 s의 y년 시황 점수, `c(k,y)` = 회사 k의 y년 실적 점수 (둘 다 −2~2 실수). `rand()` = 0~1 균등 난수, `N(0,σ)` = 정규 난수, `clamp(x,a,b)`. 능력치·성향은 내부에서 실수로 저장하고 화면엔 반올림합니다.
- 모든 난수는 판마다 정한 시드(`world.seed`)의 PRNG로 만듭니다. 세계용과 인생용 스트림을 나눠서, 같은 시드면 (플레이어가 회사를 세우지 않는 한) 같은 업계 역사가 나옵니다.

## 1. 시간과 한 해 루프

### 1.1 배속과 플레이 시간
| 항목 | 값 |
|---|---|
| 1배속 | 1년 60초 (SPEC) |
| 배속 단계 | 일시정지 · 1 · 2 · 4 · 8배 (SPEC) |
| **권장 기본 배속** | **4배 = 1년 15초** |
| 자동 보정 | 유아(1~6세) 해는 ×2, 은퇴 후(`is_retired`) 해는 ×1.5. 플레이어 배속에 곱함 |
| 시계가 멈추는 때 | 큰 사건, 구직 화면, 행동 메뉴, 캐릭터 만들기 |
| 시계가 안 멈추는 때 | 작은 사건 카드 (15초 실제 시간 타이머, 배속과 무관) |
| 연말 결산 | 그 해 열린 카드가 모두 닫힌 뒤 (시계는 100%에서 대기) |
| **자동 (v0.2 기본)** | 사건 없는 해는 0.6초, 사건이 있으면 카드에서 기다림 (작은 사건 15초·결과 4초, 큰 사건은 멈춤). 배속 1·2·4·8배는 위 규칙 그대로. "다음 사건까지 ▶▶"는 다음 사건 카드까지 해를 넘김 |

**한 판 목표: 기본 4배로 약 20분.**
계산(80세 사망, 60세 은퇴): 유아 6년 × 7.5초 + 7~60세 54년 × 15초 + 61~80세 20년 × 10초 = 1,055초(약 17.6분) + 큰 사건 12~16개 × 평균 10초 ≈ 20분.
8배 약 11분 · 2배 약 37분 · 1배 약 75분(감상용).

### 1.2 한 해 순서
| 단계 | 시점(그 해 진행률) | 하는 일 |
|---|---|---|
| ① 생일 | 0% | 나이 +1, 생애 단계 갱신, 숨은 재능 발견 판정(2.4) |
| ② 자연 변화 | 0% | 능력치 성장·노화(2.2~2.3), 성향 환경 이동(3.2), 질병 발병 판정(9.3) |
| ③ 세계 갱신 | 0% | 분야 시황 m(s,y) → 회사 실적 c(k,y) → 기술·점유율 → 1위·인수·파산·설립(6장). 업계 연표 기록, 그 해 헤드라인 1줄 |
| ④ 제도·관계 처리 | 0~5% | 진학·졸업·입대·전역·정년, 구조조정·스카우트·피인수·파산·계약 종료, 부모 사망, 자녀 성장, 연애·결혼·출산·집 판정 → 시스템 트리거(1.5) |
| ⑤ 사건 | 10~85% | 트리거·강제 사건 먼저, 그다음 추첨 사건(1.3)을 고르게 배치 |
| ⑥ 연말 결산 | 100% | 경제 결산(경제 모듈) → 승진·평판(5.5) → 행복 이동(2.5) → 성향 회귀(3.2) → 사망 판정(9.2) |
| ⑦ 기록·저장 | 100% | 연표 기록, 반도체 순간 정리, 자동 저장(12장). 사망이면 엔딩으로 |

사건의 `do`가 만든 트리거(예: `job:search` → `job_search`)는 **다음 해 ④**에서 처리합니다. `goto`와 `job:hire`처럼 즉시 일어나는 것만 예외입니다.

### 1.3 사건 추첨
**한 해 사건 수 N** (큰 사건 포함, 최대 3)
| 단계 | N=0 | N=1 | N=2 | N=3 | 평균 |
|---|---|---|---|---|---|
| infant | .40 | .50 | .10 | 0 | 0.70 |
| child | .25 | .50 | .20 | .05 | 1.05 |
| teen | .10 | .45 | .35 | .10 | 1.45 |
| young | .10 | .40 | .35 | .15 | 1.55 |
| middle | .15 | .45 | .30 | .10 | 1.35 |
| senior | .25 | .50 | .20 | .05 | 1.05 |

80세 인생이면 사건이 대략 100개(큰 사건 포함)입니다.

**뽑는 순서**
1. 올해 생긴 트리거(1.5)에 걸린 사건 + `forced: true`이고 조건이 맞는 사건을 모아 `priority` 높은 순으로 줄 세웁니다. 큰 사건은 한 해 최대 2개, 넘친 것은 다음 해로 미룹니다(조건이 맞으면 `age` 범위가 끝났어도 1년 유예).
2. N = max(N, 1번 개수), 최대 3. 남은 자리 = N − 1번 개수.
3. 남은 자리를 일반 후보에서 **가중 무작위·중복 없이** 뽑습니다. 일반 후보 = `trigger`가 없고 `forced`가 아니며 `age`·`year`·`when`·`market`이 맞고, `once` 사건이면 아직 안 본 것.
   - 추첨으로 뽑히는 큰 사건(`big: true`)은 한 해 1개, 직전 추첨 큰 사건 뒤 2년 간격.
   - 같은 해에 `tags` 첫 값이 같은 사건은 최대 2개. 같은 id는 한 해 1번.
4. 배치: 1개 → 40% 지점, 2개 → 25%·65%, 3개 → 15%·45%·75%. 1번 사건이 앞자리.

**최종 가중치**
```
w' = weight × B × T × S × R
B = Π (1 + k × x)  … 사건 bias 항목마다. 성향이면 x = 축/100 (−1~1), 능력치면 x = (값−50)/50. clamp(B, 0.2, 3)
T = 특징 배수의 곱 … 사건 tags × 3.4 표
S = 반도체 접점 배수 … 7장 (선택지 중 하나라도 semi 효과가 있는 사건만)
R = 0.25           … once가 아닌 사건이 최근 5년 안에 떴으면, 아니면 1
```
**v0.2 반복 규칙** (위 R 대신, `events.js repeatOk`)
- 사건은 **한 인생에 한 번**. `repeatable: true`면 `repeat_gap`(기본 10년) 뒤 다시 후보 (다시 열린 직후 간격의 2배 안은 ×0.5).
- 트리거에 묶인 사건(결혼·출산·구직·진로·회사 운명 등)은 트리거가 생길 때마다 뜨되, 조르는 트리거(`proposal`·`baby_chance`·`house_chance` 3년, `scout` 4년)는 같은 사건이 그 간격 안에 다시 뜨지 않음. 프러포즈는 같은 연인에게 두 번까지.
- `again:n` 다시 묻기는 조르는 트리거 사건이면 한 번까지만 (재수 같은 진로 흐름은 그대로).
- 비슷한 사건 막기: 최근 5년 안에 뜬 사건과 문장 앞 12글자가 같거나 선택지 이름이 똑같은 사건은 추첨 후보에서 뺌.
- GPT 공식형 사건(`events/gpt/`, 선택지 2개 중 하나에 "쉬어/쉬고")은 가중치 ×0.4.
- 한 해 사건 수 N: 일반 후보가 6개 이상인 해는 35% 확률로 N + 1 (한 번씩만 뜨는 사건을 그 나이대가 지나기 전에 쓰게).
- `later`(SPEC): 고른 선택지의 `later`는 `s.later[{id, year, made, from, pick, ctx}]`에 저장되고, 그 해 ⑤에서 가중치와 상관없이 강제로 띄움 (조건이 안 맞으면 3년까지 기다렸다가 버림). 카드 위에 "그때 그 선택… (그 해 · 고른 선택지)".
- 연표: 사건 선택은 "질문 요약 → 내 선택 → 결과" (`recap`, 없으면 `text` 첫 문장 30자 안팎). 선택으로 생긴 입사·결혼 줄보다 앞에 기록.
`bias` 예: `"bias": { "trait.risk": 0.5, "sociability": 0.3 }` → 모험가일수록, 사교성이 높을수록 잘 뜸.

### 1.4 사건 처리 규칙
| 규칙 | 내용 |
|---|---|
| 선택지 숨김 | 선택지에 `when`이 있고 안 맞으면 숨김. 보이는 선택지가 2개 미만이면 사건을 건너뜀 (트리거 사건은 남은 선택지로 진행) |
| 기본값 | `default`가 숨겨졌으면 보이는 첫 선택지. 작가는 `default`에 `when`·`check` 없는 선택지를 두는 것을 권장 |
| 성향 자동 선택 (설정, 기본 꺼짐) | 작은 사건이 시간 초과일 때 `default` 대신: 선택지마다 `trait.*` 효과 중 내 특징(축 절댓값 ≥ 50) 방향과 부호가 같은 개수를 세어 가장 많은 선택지 (1개 이상일 때, 동점이면 `default` 우선) |
| 판정 `check` | 성공 확률 p = clamp(0.5 + (값 − dc)/50 + 특징 보너스(3.4), 0.1, 0.9). 값 = 능력치, `trait`이면 (축+100)/2. 성공 → 선택지 `effects`·`result`, 실패 → `fail.effects`·`fail.result` (선택지 `effects`는 적용 안 함). 큰 사건 화면에는 대략 가능성(높음/보통/낮음)을 보여 줌 |
| 효과 적용 순서 | `do` → 능력치·성향·행복·평판·친구 → `cash`/`debt` → `flag` → `semi` → `title_progress` → `goto`. 그다음 `result`의 자리표시자를 채움 (그래서 `child:add` 뒤 {child}는 새 아이 이름) |
| 성향 효과 | 값 × 나이 가소성 (3.2) |
| 능력치 효과 | 그대로 더하고 0~100으로 자름 |
| 돈 상대값 | `"@토큰*배수"`, 배수 음수 허용 (`"@salary*-1.5"` = 연봉 1.5배만큼 지출). 현금이 모자라면 모자란 만큼 `debt` |
| `goto` | 이어지는 사건도 `when`을 다시 확인, 안 맞으면 건너뜀. 그 해 사건 수에 안 셈 |
| `again:n` (do) | 이 사건은 n년 동안 트리거·추첨 모두 쉬고, n년 뒤에는 트리거 없이도 후보가 됨(다른 조건은 확인). `once`여도 다시 뜸 |

### 1.6 상태 플래그 (`is_` 접두)

|---|---|

### 2.5 행복 (0~100)
사건 효과는 즉시 반영하고, 연말에 목표치 쪽으로 25%씩 움직입니다: `H ← H + 0.25 × (H_target − H)`.
```
H_target = 50
  + 돈:  현금 ≥ @salary → +5 · 빚 > 연봉×3 → −8 · 순자산 < 0 이고 무직 → −12

  + 관계: 결혼 +8 (연애 +5) · 자녀 1명당 +3 (최대 +9) · (friends − 50)/10
  + 건강: (체력 − H_exp(나이))/5 · 만성 질병 1개당 −3 · 암·우울증 −8
  + 특징: 3.4 표
clamp 0~100
```

## 3. 성향 축과 특징

### 3.1 시작값

**쓰는 곳**

| 인문계 | — | 기본 | 3 | 대학 G +3 |
| 실업계·특성화고 | — | 선택 | 3 | 산업기능요원 자격, 기능직·생산직 구직 z +0.3 |
| 마이스터고 | 2010 입학 | 손재주 check dc 50 | 4 | 반도체 오퍼레이터·설비 구직 z +0.6, 산업기능요원 자격. 대학은 '선취업 후진학'(4.5) |
| 과학고·영재고 | 1983 | 지능 ≥ 75, check dc 85 | 5 | 대학 G +8, 대졸↑이면 연구·설계 구직 z +0.3 |
| 산업체 부설 고교 | 1977~1994 | 조립 생산직 취업과 함께 | 2 | 재직하며 3년 뒤 졸업, 산업기능요원 자격 |
| 고교 안 감 | — | — | — | 학력 "무관". 검정고시 사건(작가용)이면 "고졸", tier 2 |

### 4.4 성적 G와 school_tier
**성적 G (0~100)** — 학교에 다니는 동안 매년 다시 계산합니다.
```
G = 0.55×지능 + 0.15×멘탈 + 0.15×(diligence+100)/2 + 0.15×공부량 + 2×(경제력−3) + 고교 보정(4.3) + N(0, 8)
공부량 = 50 + '공부하기' 행동 1번당 25 (최대 100)
```
**school_tier (1~5, 5가 최상위)** — 마지막으로 다닌 학교 기준.
| G | ≥ 85 | 75~84 | 60~74 | 45~59 | < 45 |
|---|---|---|---|---|---|
| 대학 tier | 5 | 4 | 3 | 2 | 1 |

- 전문대: 위 값 −1 (최소 1). 반도체장비과 같은 특화 학과는 +1.
- 대학원: max(학부 tier, 대학원 입학 때 G로 정한 tier).
- 고졸로 끝나면 4.3 표.

### 4.5 대학·대학원 진학
- **4년제 합격** p = clamp(진학률(y) × (0.6 + G/100) + 0.1 × 재수 횟수, 0.05, 0.97). 진학률이 낮은 1970년대엔 G 60이어도 약 31%, 2005년엔 약 97%.
- 불합격 → `is_rejected`, 같은 해 college_choice를 다시 띄움 (4년제 선택지는 숨김).
- **전문대 합격** p = clamp(0.6 + G/100, 0.6, 0.98). 실패하면 같은 처리.
- **재수** (`school:retry`): 1년 공백, 다음 해 G +5, 최대 2번.
- **대학원**: grad_school에서 고르면 자동 입학. 석사 2년, 박사는 석사 포함 연속 6년.
- **선취업 후진학**: 마이스터고·실업계 졸업 후 재직 3년↑이면 작가용 사건으로 야간·계약학과 진학 (재직 유지, 4년 뒤 대졸).

### 4.6 전공
`jobs.json majors` 표를 씁니다. `do: "major:<group>"`의 group 안에서 엔진이 고릅니다.
- 그 학교 종류(`levels`)와 생긴 해(`since`)가 맞는 것만 후보.
- 가중치: 기본 1, 지능 ≥ 70이면 물리학·반도체공학·전자공학 ×1.5, 손재주 ≥ 65면 기계공학·반도체장비과 ×1.5.
- `semi` 그룹: 2006년 이후 4년제는 30% 확률로 반도체공학(계약학과 포함), 아니면 전자공학. 전문대는 1995년 이후 50% 확률로 반도체장비과.
- 구직: 지원 직종이 전공 `fits`에 있으면 z +0.5. 대졸↑이 필요한 현장 직종(group 현장)에 `nonsci` 전공으로 지원하면 z −0.4.

## 5. 커리어

### 5.1 일자리 구조
일자리 = 직종(`jobs.json`) × 회사(`companies.json`) × 고용형태 × 근무지.
| 필드 | 정하는 법 |
|---|---|
| `career.job` | 직종 id |
| `career.company` | 회사 id. 직종 `sectors`가 비면 null (일반 직업, 생태계 직업) |
| `career.client` | 원청 id. 협력사(회사에 `clients`가 있음)면 그 `clients` 중 근무지에 공장이 있는 곳, `serves: fab` 직종이면 근처 팹 회사 |
| `career.region` | 근무지. 회사 `regions` 중 (그 지역 `fab_since` ≤ 올해, 또는 `fab_since` 없음)인 곳을 내 지역 → 같은 권역(`area`) → 아무 곳 순으로. 하나도 없으면 첫 지역 |
| `career.employment` | 고용형태 |
| `career.ladder`, `career.rank` | 직급 사다리 id (고용형태 owner면 owner 사다리), 사다리 안 위치 (0부터) |
| `career.years` | 현 회사 근속 연수 |
| `career.exp{job}` | 직종별 누적 경력 연수 |
| `career.salary_mod` | 협상·스카우트로 쌓인 연봉 보정 비율 (경제 입력) |

근무지가 다른 권역이면 이사합니다 (`profile.region` 변경, friends −5). 해외 근무는 `move:overseas`로만.

### 5.2 구직
**공고 만들기** (구직 화면 한 번에 6개)
1. 후보 = (직종, 회사, 고용형태) 조합 중: 직종 `since` ≤ 올해, 회사가 설립됐고 살아 있음, 학력 충족, 능력치가 요구치 −15 이상, 복무 중이 아님.
2. 회사마다 올해 채용 여부: rand() < clamp(0.5 + 0.25 × c(k,y), 0.05, 1).
3. 6개 슬롯: 반도체 직종(touch core·near·eco) 최소 2개 (반도체 순간 없이 30세↑면 3개, 7장), 반도체 밖(none) 최소 1개, 쉬운 자리(계약·파견·일용·아르바이트) 최소 1개. 나머지는 합격 확률 × 선호도 순.
4. 합격 가능성은 말로 보여 줍니다: ≥ 70% 높음 · 40~69% 보통 · 15~39% 낮음 · < 15% 희박.
5. 최대 3곳 지원 → 각각 판정 → 여러 곳 붙으면 플레이어가 고름. 다 떨어지면 무직 유지 (다음 해 다시 `job_search`).

**합격 확률**
```
z = −0.6
  + k_m × m(s,y)               k_m: core 0.6 · near 0.4 · eco 0.25 · none 0.15 (none은 m 대신 국내 경기 g(y))
  + 0.4 × c(k,y)               회사가 없으면 0
  + 0.4 × (내 학력 − 요구 학력) 단계 차, 최대 +0.8
  + 0.25 × (school_tier − 3)    요구 학력이 대졸↑인 직종만
  + 능력치: 요구 이상이면 min(0.75, (값−요구)/20), 미만이면 (값−요구)/10  … 요구 능력치마다 더함
  + 전공: fits +0.5 · 현장 대졸 직종에 nonsci −0.4
  + 지역: 같은 지역 +0.3 · 같은 권역 +0.15 · 해외 근무지인데 석사↑도 해외 경험도 없음 −0.4
  − 0.3 × ((회사 salary + stability)/2 − 3)   좋은 회사일수록 경쟁이 치열 (판 랜덤 반영값)
  + 재능 favors +0.5 · 자격증 +0.3 · 고교 유형 보정 (4.3)
  + 경력: 0.1 × 같은 직종 경력 연수 (최대 +0.8) · (평판−50)/100 (경력직만)
  + 고용형태: 정규 −0.2 · 계약 +0.3 · 파견 +0.5 · 일용 +0.8
  + 인맥: friends ≥ 70 → +0.2
  + 나이: 경력 없는 35세↑ −0.1×(나이−35) (최소 −1.5) · 55세↑ −0.5 (service·craft 일용·serves 직종은 나이 감점 없음)
  + 시대: 1965~1995년 학력 무관·고졸 생산직(operator, assembler, factory_worker) +0.4
  + R&D 적합도 (5.11)
P = clamp(1 / (1 + e^−z), 0.02, 0.95)
```
**예시**
| 상황 | z | P |
|---|---|---|
| 2018년, 전자공학 대졸 tier 3, 지능 72 → 삼송전자 공정 엔지니어 정규직 (m = +2, c = +2, 같은 권역) | 1.6 | 83% |
| 같은 사람이 1998년 (m = −2, c = −1.5) | −2.2 | 10% |
| 1985년, 공고 졸업, 체력·멘탈 55 → 하이닉수 오퍼레이터 정규직 (m = −2, c = −1.5, 같은 지역) | −1.55 | 18% |
| 같은 사람이 1988년 (m = +2, c = +1.5) | 2.05 | 89% |

### 5.3 첫 취업 offer 슬롯 (first_job)
first_job은 "이미 붙은 곳 3개 중 고르기"입니다. 엔진이 5.2 후보로 몰래 판정을 돌려 (최대 12번) 붙은 곳을 채웁니다.
| 슬롯 | 고르는 기준 | 못 채우면 |
|---|---|---|
| `offer1` | 붙은 곳 중 회사 salary 등급(회사 없으면 직종 기본 연봉) 최고 | 반도체 계약직·파견직 |
| `offer2` | 붙은 곳 중 집에서 가장 가까운 곳 (같은 지역 → 권역) | 동네 일반 직업 (part_timer, factory_worker, farmer 등) |
| `offer3` | 다른 길: offer1·2와 touch가 다른 곳 (둘 다 반도체면 none, 아니면 반도체) | part_timer |

- 15~17세(고교를 안 간 경우)는 학력 "무관" 직종만: 조립·농사·가게·공장 위주.
- 반도체 직종을 처음 가지면 엔진이 반도체 순간 "{company} 첫 출근"을 자동 기록합니다 (kind = 직종 touch). 그 직장을 준 선택지에 이미 `semi` 효과가 있으면 생략합니다.

### 5.4 직급 체계
`jobs.json rank_ladders` 요약:

| service | 급식·보안·시설·미화·사감·통근버스·세탁, 간호 | 사원 → 주임 → 조장 → 팀장 → 소장 | — |
| academic | 교수 | 시간강사 → 조교수 → 부교수 → 정교수 | — |
| public | 산업부 공무원, 공무원 | 주무관 → 사무관 → 서기관 → 부이사관 → 고위공무원 | — |
| teacher | 교사 | 교사 → 부장교사 → 교감 → 교장 | — |
| owner | 자영업 전부 | 개업 → 자리 잡음 → 단골 가게 → 확장 → 지역 명소 | 실적으로 오르내림 (5.8) |
| creator | 유튜버 | 구독자 100명 → … → 100만 | 실적으로 오르내림 |
| none | 아르바이트, 투자자, 기사 | 없음 | — |

- **입사 직급**: 박사 → corporate·research rank 2 (과장·책임). 석사 → rank 0이지만 근속 2년으로 침. 고졸·전문대졸이 corporate 사다리면 단계마다 `min_years` × 1.5.
- **학력·전공 맞춤 (v0.2, `career.fitMult`)**: 구직 선호에 곱함 — 전공 `fits` ×3, 공대(`semi|materials|other_eng`) 대졸↑의 반도체 현장 직종 ×2.5, 석사 연구·현장 ×2.5(그 밖 ×0.2~0.6), 박사 연구·교수·국책연 ×6(그 밖 ×0.1), 대졸↑의 학력 무관·고졸 직종 ×0.3, 공대생의 전공 밖 서비스·일반 직종 ×0.3. 합격 확률 z에도 공대 현장 +0.3, 박사 연구 +0.5. 박사에게는 국책연구소(`eco_gov_lab`, 대전) 자리가 공고에 더해짐. 석사↑의 세 번째 offer는 학위에 맞는 다른 길.
- **세부 직업 (v0.2)**: 회사 분야에 맞는 `job_matrix` 직무 중 학력에 가까울수록(같은 단계 ×3, 한 단계 아래 ×2) 그리고 대학원 전공(`education.specialty`, 석·박사 졸업 때 전공 계열에 맞는 축 값으로 정함)과 축이 맞으면 ×6.
- **경력 이직**: 같은 사다리면 직급 유지 (스카우트는 30% 확률로 +1).
- 2019년 이후 회사들이 직급 단계를 줄인 흐름은 표시 이름만 바꾸는 선택 기능으로 둡니다 (예: CL1~4). 규칙은 같습니다.

### 5.5 승진·평판
> v0.2 튜닝(life_sim): 임원으로 오르는 판정은 `promo_base` ×2, 필요 연수 ×0.6. 부장·수석 쪽 피라미드 보정은 0.22·0.13 (대졸 회사원·연구원 부장↑ 30~45%, 임원 3~8% 목표).

**평판 (0~100)**: 입사 50, 이직하면 `50 + 0.5 × (이전 평판 − 50)`. 매년 +0.5 (근속 10년까지) + clamp((핵심 능력치 − 60)/20, −1, 1) + 특징(3.4) + 사건.

**승진 판정** (연말, 현 직급에서 `min_years`를 채웠을 때)
```
P = promo_base[rank] × (1 + s) × 회사 보정
s = clamp( (평판−50)/100 + (key_stat−60)/200 + 특징 보정(3.4) + 0.05 × 초과 근속 연수
           + 재능 favors 0.1 + R&D 보정(5.11), −0.5, +0.6 )
회사 보정: c ≤ −1 → ×0.3 (승진 동결) · c ≥ 1.5 → ×1.2
```
- `max_tries`가 있는 직급은 그 횟수만큼 떨어지면 더 오르지 않습니다 → 플래그 `career_plateau` ("만년 차장" 사건용).
- 임원 직급(`exec_from`)으로 오르는 판정이 성공하면 바로 올리지 않고 `exec_offer` 트리거.
- **임원**: 매년 재계약 p = clamp(0.75 + 0.1 × c + (평판 − 70)/100, 0.3, 0.95). 실패하면 퇴임 (50세↑면 `retired`, 아니면 무직). 65세 자동 퇴임. 전무·사장 승진은 같은 공식.
- 생산·기능 사다리는 key_stat이 손재주, service·teacher는 사교성.

### 5.6 스카우트·이직·전적
**스카우트 (`scout`)** — 매년 판정
- 조건: `is_employed`, 정규·계약직, 근속 3년↑, 사다리 corporate·research·production·craft, 임원 아님, 지난 스카우트 뒤 4년.
- p = clamp(0.02 + 0.003 × (평판 − 50) + 0.02 × max(0, m(s,y)) + 인싸 0.02 + 재능 favors 0.03 + R&D 보정(5.11), 0, 0.2).
- 제안: `{rival}` (1.4), 연봉 보정 +20~50% (`salary_mod`, 균등), 근무지 = rival 근무지 중 하나 (해외 회사면 해외), 30% 확률로 직급 +1.

**자발적 이직**: '이직 알아보기' 행동 → 구직 화면 (재직 유지). 붙으면 옮깁니다. 근속은 0, 직종 경력은 유지, 평판은 이직 공식.

**전적 `job:transfer`**: 같은 원청을 상대하는 협력사·자회사로 옮김. 직종 유지, `salary_mod` −0.15, 근무지 같음. 계약 종료 상황이면 같은 회사 다른 사업장으로 이동 p 0.5 (실패하면 무직).

### 5.7 구조조정·희망퇴직·계약
| 단계 | 규칙 |
|---|---|
| 회사 발표 | c(k,y) ≤ −1.5면 그 해 구조조정 p 0.5 (c = −2면 0.7). market_history `korea` 점수가 −2인 해(예: 1985, 1998, 2001, 2008, 2023)는 c ≤ −1인 국내 회사도 p 0.5 |
| 내가 대상 | p = clamp(0.15 + 0.15×[50세↑] + 0.1×[rank ≥ 3] + (50 − 평판)/200 + 0.15×[계약·파견] − 0.03×(stability − 3) − 0.05×[순응형], 0.05, 0.7) → `layoff_target` |
| 파견·일용 | c ≤ −1인 해 재계약 안 됨 p 0.25 (c = −2면 0.4) → 알림만, 무직 |
| 계약직 | 2년마다 갱신 p = 0.8 + 0.1 × c, 정규직 전환 p = 0.1 + 0.05 × (평판 − 50)/10 |
| 위로금 | 사건의 `cash` 상대값 (`@salary*0.5~2`). 법정 퇴직금은 경제 모듈 |

### 5.8 자영업·부업·창업
**실적 b (−2~2)** — 매년
```
b = clamp(0.5 × L + 0.3 × K + N(0, 0.6), −2, 2)
L = serves가 fab_region이면 근처 팹 회사들의 c 평균, 아니면 국내 경기 g(y)
K = (핵심 능력치 − 50)/25 + 재능 favors 0.5
```
- 2년 연속 b ≥ 1 → owner 사다리 한 칸 위, 2년 연속 b ≤ −1 → 한 칸 아래, 가장 아래에서 2년 연속 b ≤ −1.5 → 폐업 (`shop_closed`, 무직).
- 수입은 경제 모듈 `business_income`에 b와 단계를 넘김.
- **부업** (`job:side:<id>`, 최대 2개): 원룸 임대(landlord), 개미 투자자(반도체주를 1년 넘게 들고 있으면 자동 표시), 유튜버(사건으로 시작). 본업과 함께 갑니다. 조건 키 `job`은 본업과 부업을 모두 확인합니다.
- **내 회사 창업** (`job:found:<sector>`): 6.6 신규 회사 규칙으로 그 분야에 회사를 만들고 나는 그 회사 owner (corporate 사다리 '사장'으로 표시). 회사 운명이 곧 내 운명입니다.
- **`angel_investor`**: 5년 뒤 결과 — 30% 투자금 ×5, 30% ×1, 40% 0. 엔진이 결과 플래그 `angel_win`·`angel_even`·`angel_lost`를 붙이고 작가 사건으로 알림.

## 6. 시황과 회사 운명

### 6.1 분야 시황 m(s,y)
회사 운명 모델의 시장 입력은 **"그 해 분야 점수"** 하나뿐입니다. 출처만 시대에 따라 바뀝니다.
- **2026년까지**: `market_history.json`의 그 해 점수 (`cycle`, `memory`, `logic_foundry`, `equipment`, `korea`, −2~2)를 분야의 `market_mix` 비율로 섞습니다 (`companies.json` sectors). 값이 null인 키는 빼고 비율을 다시 나눕니다. 다 없으면 `cycle`, 그것도 없으면 0.

| 분야 | market_mix |
|---|---|
| memory | memory 1 |
| foundry | logic_foundry 1 |
| fabless | logic_foundry 0.6 + cycle 0.4 |
| equipment_global | equipment 1 |
| equipment_korea | equipment 0.6 + korea 0.4 |
| materials | cycle 0.6 + korea 0.4 |
| packaging | cycle 0.7 + memory 0.3 |
| construction · catering · security | 자기 점수는 korea 1이지만 `follows`(6.7)가 우선 |

- **업계 지수 I(y)** = Σ index_weight × m(s,y). 생태계 직업, 반도체주 지수에 씁니다.
- **국내 경기 g(y)** = `economy_history.json`의 `macro_score` (−2~2). 일반 직업·자영업에 씁니다.

### 6.2 2027년 이후 (자리만 둠 → FUTURE.md)
- 2027~2150년의 분야 점수는 미래 설계(`FUTURE.md`, `future_tech.json`)의 **업계 테크트리 + 사이클 모델**이 만듭니다. 이 문서는 미래 시황을 정의하지 않습니다.
- 이 문서가 기대하는 모양: 매년 market_history와 **같은 키**(`cycle`, `memory`, `logic_foundry`, `equipment`, `korea`, −2~2 실수)를 판마다(시드별) 돌려주는 함수 — 예: `future.market(y, world)`. 새 분야가 생기면 `companies.json`에 분야를 추가하고 `market_mix`로 연결합니다. 헤드라인도 같은 곳에서 받습니다 (예: `future.headline(y, world)`).
- 미래 모델이 주면 쓰는 것: 기술 이정표 달성 연도 (6.4 세대 경쟁·업계 연표), 의료 기술 (9.1 D(y)·9.3 치료), 정년·병역·진학률·출산율 변화, 새 분야, `macro_score` 대체값, R&D 적합도 (5.11).
- 미래 모델이 붙기 전 프로토타입은 2027년 이후 모든 점수 0, `macro_score` 0으로 돌립니다.

### 6.3 회사 실적 c(k,y)
```
c(k,y) = clamp( m(s,y) + a(k,y) + tech(k,y), −2, 2 )
a(k,y) = 0.6 × a(k,y−1) + N(0, σ)      … 회사 운 (0으로 되돌아오는 랜덤 워크)
         σ = 0.25 (2026년까지), 0.40 (2027년부터)
2026년까지는 c를 m(s,y) ± 1.0 안으로 한 번 더 자름 (역사 안전장치)
```
협력사는 6.7 공식을 씁니다. 회사 속성(salary·wlb·stability·growth)은 새 판을 시작할 때 각각 −1(25%)·0(50%)·+1(25%)을 더하고 1~5로 자릅니다.

### 6.4 기술 경쟁
- 회사마다 기술력 T. 시작 = 50 + 5 × (growth − 3) + 5 × (stability − 3).
- 매년 `T += N(0, 2) + 0.8 × (growth − 3) + 1.0 × c(k,y−1)` (좋은 해에 투자한 회사가 앞서감).
- `tech(k,y) = clamp(0.04 × (T − 분야 평균 T), −0.6, 0.6)`.
- **세대 경쟁**: 분야마다 4~6년(균등)에 한 번. 순위 = T + N(0, 5). 1등 T +8, 꼴찌 T −5. 업계 연표 "{company}, 차세대 공정 경쟁에서 앞서 나가요". 2027년부터는 FUTURE의 기술 이정표가 생기는 해에 세대 경쟁을 엽니다.

### 6.5 점유율·1위
- 시작 점유율 = `companies.json share`를 분야 안에서 정규화. `founded` 연도에 나타나는 회사는 그 해 share 가중치로 끼어들고 다시 정규화.
- 매년 `share ← share × exp(0.12 × c(k,y) + 0.05 × tech(k,y))` 후 분야 안에서 정규화.
- 2026년까지는 추가로 `share ← 0.7 × share + 0.3 × 기준 share`(정규화)로 당겨서, 역사 구간의 순위가 크게 뒤집히지 않게 합니다.
- **1위 등극**: 2위가 1위를 점유율로 2년 연속 (2026년까지는 3년 연속) 앞서면 순위 교체 → 업계 연표 "{year}년 {company}, {분야} 1위 등극 ({옛 1위} 추월)". 내 회사면 반도체 순간 후보.

### 6.6 위기·파산·인수·설립
`crisis` 카운터: c ≤ −1.5면 +1, c ≥ 0이면 0으로, 그 사이면 그대로.
| 운명 | 조건 | 확률/년 | 결과 |
|---|---|---|---|
| 파산 | crisis ≥ 2, 분야 1위 아님, 분야에 살아 있는 회사 3곳↑ | 0.06 × crisis × (6 − stability)/3 × H. H = 0.25 (2026년까지) / 1 (이후). 2027년부터 crisis ≥ 6이면 확정 | 회사 사라짐. 직원 → `company_bankrupt` (무직). 그 회사를 원청으로 둔 협력사 사업장 → `contract_lost`. 주가 0 (경제) |
| 인수 | crisis ≥ 1, 정규화 점유율 < 0.2, 같은 분야(없으면 가까운 분야: 장비 해외↔국내, 메모리↔파운드리)에 c ≥ 0.5이고 점유율 ≥ 0.25인 회사가 있음 | 0.08 × crisis × H2. H2 = 0.3 (2026년까지) / 1 (이후). 2027년부터는 건강한 작은 회사도 0.01 | 인수 회사 = 점유율 × c 최대. 점유율 합침, T는 큰 쪽. 직원 70%는 승계 (`company_acquired`, 회사 id가 인수 회사로), 30%는 승계 대신 `layoff_target` |
| 설립 (역사) | 회사 `founded` 연도 | 확정 | 등장. 그 전엔 입사·주식 불가 |
| 설립 (2027~) | 분야에 살아 있는 회사 < 4 | 0.10 + 0.1 × max(0, m(s,y)) | `spawn_names`에서 이름 (다 쓰면 이름 + 숫자), share 0.05, T = 분야 평균 − 8, salary 3·wlb 3·stability 2·growth 4, regions = 분야 기존 회사 지역에서 1~2개. FUTURE가 새 분야를 열면 그 분야 회사도 같은 규칙 |
| 설립 (플레이어) | `job:found:<sector>` | 확정 | 2027 규칙과 같되 share 0.01, 이름은 템플릿("{성}테크" 등), 2026년 이전에도 가능 |

- 분야마다 살아 있는 회사는 항상 2곳 이상, 최대 6곳.
- 2026년까지는 판 전체 파산이 대개 0~2건이 되도록 맞춥니다 (14장).
- 실존 회사를 떠올리게 하는 패러디 이름을 "늘 망하는" 회사로 정해 둔 스크립트는 없습니다. 운명은 시드 랜덤뿐입니다.

### 6.7 협력사
| 분야 | 실적 공식 |
|---|---|
| 급식·보안 (`follows: clients`) | c = clamp(0.6 × 살아 있는 clients의 c 평균 + 0.4 × m(korea) + a, −2, 2) |
| 팹 건설 (`follows: capex`) | c = clamp(0.5 × clients c 평균 + 0.5 × capex(y) + a, −2, 2), capex(y) = (m(memory, y−1) + m(foundry, y−1)) / 2 — 호황 다음 해에 팹을 짓습니다 |

- 원청이 파산하면 그 원청 사업장에서 일하던 협력사 직원은 `contract_lost`. 원청이 인수되면 계약 승계 p 0.7 (실패하면 `contract_lost`).
- 원청이 하나도 안 남은 협력사는 매년 p 0.5로 근처 팹 회사를 새 원청으로 얻고, 못 얻으면 crisis +1.
- `serves: fab` 직종(통근버스·방진복 세탁)은 `career.client` 회사의 운명을 그대로 따릅니다. `fab_region` 직종(치킨집·원룸)은 근처 팹 회사들 c 평균이 장사(5.8 L)에 들어갑니다.

## 8. 관계

### 8.1 부모
- 내가 태어날 때 부모 나이 = `character.json family.parent_age` 범위에서 균등. 상태 `relations.parents = [{role, birth_year, alive, job, semi}]` (SPEC의 `parents_alive`는 여기서 계산: 살아 계신 분이 있으면 true).
- 매년 부모 각각 사망 판정 = 9.2 공식 (체력 = H_exp, 습관·질병 없음, 경제력 = 가정 경제력).
- 돌아가시면 `parent_died` 트리거, 알림 "{year}년, 아버지(어머니)가 세상을 떠나셨어요.", 행복 −15 (화목도 ≥ 60이면 −20). 두 분 다 돌아가시면 상속 = 경제 모듈 `inheritance(wealth, siblings, year)`. 부모 직업이 반도체였으면 순간 후보 "아버지(어머니)의 사원증을 정리했어요" (family).
- 가정 경제력은 어린 시절 사건 `do: "wealth:±1"`로 바뀝니다.

### 8.2 친구 (`friends` 0~100)
- 시작 40 + (사교성 − 50)/5. 학교 다니는 해 +3, 30세↑ 매년 −1, 다른 권역으로 이사 −5, 특징(3.4), 사건.
- 쓰임: 행복 목표, 구직 인맥 (≥ 70 → z +0.2), 작가 조건, 엔딩 관계 점수.

### 8.3 연애
- **연애 시작**: '연애 상대 찾기' 행동 p = clamp(0.25 + (사교성−50)/150 + (외모−50)/200 + (행복−50)/300 + 인싸 0.05, 0.05, 0.8). 행동 없이도 17~45세에 연인이 없으면 매년 p = clamp(0.10 + 0.1 × (사교성−50)/50 + 인싸 0.05, 0.02, 0.3). 사건 `do: "partner:new"`로도 시작.
- **연인 `relations.partner`**: `{name, gender, birth_year, job, semi, met_year, met_at, love, married}`.
  - 나이: 내 나이 ± N(0, 3). 성별: 기본 반대 성별, 설정으로 변경 (오너 결정, 16장).
  - 직업: 회사에서 만났으면 같은 회사 다른 직종 (사내 커플), 아니면 시대별 부모 직업표와 비슷한 분포. 반도체 직업일 확률 = 내 직종 touch core 30% · near·eco 15% · `near_fab` 10% · 그 외 5%. 반도체면 순간 후보 (family).
  - 애정 love: 시작 50~80. 매년 +2 (행복 ≥ 60) −3 (워커홀릭) −5 (내가 무직 2년↑) + N(0, 5) + 사건.
- love < 20 → 연애 중이면 이별 p 0.5, 결혼 중이면 이혼 p 0.2 (1990년 전 ×0.3).

### 8.4 결혼 (`proposal` 트리거)
- 조건: 연인 있음, 사귄 지 1년↑, 20세↑, love ≥ 60.
- p = 0.05 + 0.35 × exp(−((나이 − M(y, 성별)) / 6)²). M = 그 해 평균 초혼 나이 (대략값):

| 연도 | 1960 | 1970 | 1980 | 1990 | 2000 | 2010 | 2020 | 2026~ |
|---|---|---|---|---|---|---|---|---|
| 남 | 25 | 27 | 27 | 28 | 29 | 32 | 33 | 34 |
| 여 | 21 | 23 | 24 | 25 | 26 | 29 | 31 | 32 |

- 2027년 이후는 FUTURE 쪽이 정하기 전까지 2026년 값. 비혼도 정상 결말이고, 결혼은 행복·관계 점수에만 유리합니다.

### 8.5 출산 (`baby_chance` 트리거)
- 조건: `is_married`, 아내(내가 여자면 나) 나이 ≤ 44, `childfree`·`family_complete` 아님.
- 첫 아이 p = 0.5 × f(y), 둘째부터 p = 0.25 × f(y) (최대 0.6). 가정적이면 ×1.3.
- f(y) = clamp(합계출산율(y) / 2, 0.3, 1.5). 합계출산율 대략값:

| 연도 | 1960 | 1970 | 1980 | 1985 | 1990 | 2000 | 2005 | 2010 | 2015 | 2020 | 2023~2026 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| TFR | 6.0 | 4.5 | 2.8 | 1.7 | 1.6 | 1.5 | 1.1 | 1.2 | 1.2 | 0.84 | 0.72 |

- 2027년 이후는 FUTURE 쪽이 정하기 전까지 0.75.
- 아이 `relations.children[]`: `{name, gender, birth_year, intelligence, dexterity, health, edu, major_group, job, company, semi, encouraged, alive}`. 능력치 3개 = 부모 평균 ± N(0, 12) (배우자 능력치는 50 ± 15로 생성).

### 8.6 자녀 성장과 진로 (추상 시뮬)
- 자녀는 사건 없이 표로 자랍니다: 7세 입학, 16세 고교 (4.2 표·경제력), 19세 대학 판정, 졸업 뒤 취업, 결혼 (8.4 곡선, 연 p 0.3).
- **자녀가 반도체 직군이 될 확률** (취업하는 해에 1번)
```
p = base(y) + 0.10×[내가 core 경력] + 0.05×[내가 near·eco 경력] + 0.05×[near_fab]
    + 0.15×[encourage_semi] − 0.05×[encourage_medic] + 0.05×[자녀 지능 ≥ 70]
    + 0.10×[70세↑이고 내 반도체 순간 0개]
base: 1985년까지 0.03 · 1986~2005 0.05 · 2006~ 0.07 (2027년부터 FUTURE가 바꿀 수 있음). 최대 0.6
```
  - 반도체면 직종: 대졸↑·지능 ≥ 65 → 공정·수율·회로·소자 중, 고졸·전문대 → 오퍼레이터·설비, 그 외 near 직종. 회사 = 분야 회사 중 점유율 × (1 + c) 가중.
  - 내 반도체 순간 "{child}가 {company} {직종}이 되었어요" (family).
- 손주: 자녀가 결혼한 뒤 연 p 0.2로 생김 (`has_grandchild` 플래그, 수만 셈).
- 자녀 사망은 다루지 않습니다 (오너 결정, 16장).

### 9.1 기대수명 (대략값)과 기준 사망 나이 D(y)
| 연도 | ~1960 | 1970 | 1980 | 1990 | 2000 | 2010 | 2020 | 2026 | 2027~ |
|---|---|---|---|---|---|---|---|---|---|
| 출생 시 기대수명 (대략, 참고) | 52 | 62 | 66 | 72 | 76 | 80 | 83.5 | 84 | — |
| D(y) 게임 상수 | 76 | 78 | 80 | 83 | 86 | 89 | 91 | 92 | +0.1/년, 최대 97 (FUTURE 의료 기술이 올릴 수 있음) |

- 사이 연도는 선형 보간. 출생 시 기대수명은 영유아 사망이 섞인 값이라 게임 상수와 다릅니다. 게임은 1세부터 시작하고 어린 사망을 줄였으므로 D를 따로 둡니다.
- **시뮬 목표**: 출생 코호트별 평균 사망 나이 1940년생 약 76 · 1960년생 약 80 · 1980년생 약 84 · 2000년생 약 87 · 2020년생 약 89 (±2). 안 맞으면 D 표를 조정합니다.

### 9.2 사망 확률 (연말, 매년)
```
q = 1 − (1 − q_main) × (1 − q_cancer) × (1 − q_heart)
q_main = 1 − exp(−μ)
μ = μ_age × F_h × F_cond × F_life × F_wealth × F_mood + μ_job + μ_young

μ_age    = 0.1 × exp(0.1 × (나이 − D(y)))        … 곰페르츠 곡선. 나이 = D면 연 10%
F_h      = clamp(exp(−(체력 − H_exp(나이)) / 30), 0.5, 2.5)
F_cond   = 가진 질병의 사망 배수 곱 (9.3; 암·심혈관은 q_cancer·q_heart로 따로)
F_life   = 흡연 1.6 × 과음 1.2 × 운동 0.8 (해당하는 것만)
F_wealth = 경제력 단계 1~5 → 1.2 / 1.1 / 1.0 / 0.95 / 0.9
F_mood   = 행복 ≤ 20이면 1.15
μ_job    = 지금 직종 risk (jobs.json)
μ_young  = 29세 이하만: 1950년대 0.003 · 1960년대 0.0015 · 1970년대 0.0008 · 1980년대 0.0004 · 1990년~ 0.0002 (18세 미만은 ×0.5)
110세는 확정 사망
```
- **성인 경제력 단계** = 순자산 ÷ @avg_wage: < 0.5 → 1, < 2 → 2, < 6 → 3, < 15 → 4, 그 이상 → 5. 25세 전에는 가정 경제력. SPEC 조건 키 `wealth_min`도 이 값을 씁니다.
- **참고값** (2020년, 질병·습관 없음, 체력 = H_exp, 경제력 3): 60세 0.45% · 70세 1.2% · 80세 3.3% · 90세 9%.

## 11. 엔딩·되돌아보기

### 11.1 엔딩 화면 구성 (위에서 아래로)
1. **마지막 한 줄**: "{name}, {태어난 해}~{죽은 해} ({나이}세). {지역}에서 {사인}으로 눈을 감았어요." 치매면 "가족 곁에서 조용히 눈을 감았어요."
2. **인생 칭호** + **인생 점수** (11.5)와 영역 막대 6개.
3. **특징**: 마지막 특징 최대 3개 + "가장 오래 간 특징 ({n}년)".
4. **인생 연표 요약**: 11.2 규칙으로 8~12줄.
5. **내 인생의 반도체 순간** 카드 (11.3).
6. **업계 연표** (11.4).
7. **숫자**: 최고 연봉 (그 해 평균의 몇 배), 총 경력, 이직 횟수, 최고 직급, 순자산 (그 해 평균 연봉의 몇 배), 자녀 수, 집 수.
8. **버튼**: 공유 이미지 · 연표 전체 · 자녀로 이어 살기 (11.8) · 같은 세계에서 새 인생 · 새 인생.

### 11.2 연표 요약 규칙
- 연표 항목 `{year, age, text, importance(0~3), kind, event_id}`.
- 중요도 3 = 출생·첫 직장·결혼·출산·은퇴·사망·갈림길 선택 · 2 = 입학·졸업·입대·이직·승진 (rank 3↑)·집·부모 별세·질병·회사 운명 · 1 = 작은 사건·그 밖의 승진 · 0 = 조용한 해 자동 문장.
- 요약 = 중요도 3 전부 + 중요도 2를 시간 순으로 채워 최대 12줄. 같은 해 항목이 2개 이상이면 한 줄로 합칩니다.
- **v0.2 해마다 소식 (`chronicle.js`)**: 늘 남기는 드문 소식 — 자녀 입학(7·13·16·20세), 부모님 환갑·칠순·팔순, 결혼기념일(10·25·40·50), 근속 5·10·20·30년, 재산 문턱(1천만·1억·3억·5억·10억…), 빚 완납, 내 집 값 ±, 업황 전환(반도체 회사 재직이면 회사 분야, 아니면 공장 동네). 그래도 의미 있는 줄이 없는 해는 학교 성적(단계마다 한 번) → 나이 고비 → 세상 소식(`news_general`, 패러디 이름, kind `world`). 반복 문장(중요도 0)은 학교 단계·직장마다 한 번만.
- 업적은 연표에 쓰지 않고 토스트와 엔딩 목록(`s.ach_log`)으로만.

### 11.3 내 인생의 반도체 순간
- 최대 5장: ① 첫 순간 ② kind 우선순위 core > near > eco > money > family > school > place > history 중 높은 것들 ③ 마지막 순간. 겹치면 다음 후보.
- 카드 내용: 연도, 나이, 문장, kind (그림 id `semi_<kind>`), 그 해 업계 시황 한 단어 (슈퍼호황·호황·보통·불황·대불황).
- 순간이 0개면 7장 최후 수단 3 카드 (everyday) 한 장.

### 11.4 업계 연표
- 내 인생 기간의 `world.timeline`에서 6~10개: `mine` 항목 우선 → 1위 교체·파산·인수 → 실제·미래 헤드라인 (시황 |점수| = 2인 해).
- 예: "2041년 하이닉수, 메모리 1위 등극 (삼송전자 추월)".

### 11.5 인생 점수 (0~1000)
| 영역 | 0~100 계산 | 비중 |
|---|---|---|
| 행복 | 평생 평균 행복 (20세↑ 해는 ×1.5 가중) | 25% |
| 건강·수명 | clamp(50 + 5 × (사망 나이 − 출생 코호트 목표 수명 (9.1)), 0, 100) | 15% |
| 재산 | clamp(25 × log2(1 + 최대 순자산 ÷ 그 해 @avg_wage), 0, 100) — 평균 연봉 15배면 100 | 15% |
| 관계 | 결혼 (유지·사별) 25 + 자녀 1명당 10 (최대 30) + 최고 friends × 0.3 (최대 30) + 어린 시절 화목도 ≥ 60이면 15 | 20% |
| 커리어 | 최고 평판 × 0.5 + 50 × (최고 직급 ÷ 사다리 최고 직급). 사다리 none이면 최고 평판 그대로 | 15% |
| 반도체 | min(100, 15 × 순간 수 (everyday 제외) + 20 × [core 10년↑] + 10 × [가족 반도체]) | 10% |

점수 = Σ(영역 × 비중) × 10. 화면엔 숫자와 막대만 보여 주고 등급 (S·A·B…)은 붙이지 않습니다. 어떤 삶도 낮게 매기지 않기 위해서입니다.

- 크기 목표: 한 인생 200KB 이하 (연표는 짧은 문장, 회사 기록은 연도별 c·share 숫자 배열).
- 새로고침 후 이어 하기: 작은 사건 타이머는 15초부터 다시, 큰 사건은 그대로 열림.
- **같은 세계에서 새 인생**: `world.seed`를 그대로 쓰고 캐릭터만 새로 만듭니다. 세계 난수 스트림이 인생과 분리돼 있어 플레이어가 회사를 세우지 않으면 같은 업계 역사가 됩니다.

## 15. 경제 모듈과의 약속
경제 설계 담당 (`ECONOMY.md`)이 정할 함수 목록입니다. 이 문서는 부르는 시점과 넘기는 값만 정합니다. 이름은 제안이며 ECONOMY.md 쪽 이름을 따릅니다.
| 함수 | 부르는 때 | 넘기는 값 | 받는 값 |
|---|---|---|---|
| `salary(inputs)` | 연말 결산 | 5.10 표 | `{base, bonus}` (원) |
| `business_income(job, stage, b, region, year)` | 연말, 자영업·부업 | 5.8 | 원 |
| `living_cost(year, region, household, thrift_axis)` | 연말 | 가구원 수, 성향 thrift | 원 |
| `tuition(year, type)` | 학년마다 | 학교 종류 | 원 |
| `house_price(region, year)`, `can_buy(...)` | `@house_local`, `house_chance`, `house:*` | 지역, 현금, 연봉 | 원 / 참·거짓 (+대출 조건) |
| `stock_price(company, year)` | 연말, `invest:*` | c(k,y) 역사, m(s,y), share, 파산 여부 | 원/주 |
| `index_price(year)` | `invest:semi_index` | I(y) | 지수 |
| `interest(year)` | 연말 | 빚·예금 | 이자 |
| `severance(...)`, `pension(...)` | 퇴직·은퇴 | 근속, 연봉 | 원 |
| `inheritance(wealth, siblings, year)` | 부모 사망 | 가정 경제력 | 원 |
| `child_cost(year, child_age)` | 연말 | | 원 |
| `medical_cost(condition, year)` | 진단·치료 | | 원 |
| `soldier_pay(year)` | 복무 중 | | 원 |
| `avg_wage(year)` | `@avg_wage`, 점수, 경제력 단계 | | 원 (`avg_wage_krw`) |

- 경제 결산 순서: 수입 (연봉 + 성과급 + 자영업 + 부업 + 이자 + 연금) → 지출 (생활비 + 자녀 + 학비 + 의료 + 대출 상환) → 집값·주가 갱신 → 순자산. 현금이 음수가 되면 그만큼 빚으로.

- `is_` 접두 플래그 = 엔진이 붙이고 떼는 상태 플래그 (1.6). 그 밖의 플래그는 지우지 않습니다.
- `school_tier` 방향: **5가 최상위** (companies의 1~5, wealth 1~5와 같은 방향).
- 시스템 트리거 이름 (1.5)과 반도체 순간 kind (7장)를 SPEC에 올려 작가와 같이 씁니다.
