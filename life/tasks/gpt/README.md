# GPT 작업 지시서 모음

세미툰 라이프(가제, `life/` 폴더) 기획을 위해 GPT가 맡을 일입니다. 오너가 파일 하나씩 GPT에게 주면, GPT는 그 파일 하나만 보고 끝까지 할 수 있게 썼습니다.

## 모든 작업 공통 규칙
1. **먼저 읽기**: 저장소 `AGENTS.md`, `life/docs/SPEC.md`(공통 규격, 반드시 따름), `life/docs/GAME_DESIGN.md`, 그리고 각 지시서의 "읽을 파일".
2. **브랜치**: 최신 `main`에서 `gpt/life-<작업번호>` 브랜치를 만듭니다 (예: `gpt/life-t01`). `main`에 `life/` 폴더가 아직 없으면 `claude/life-sim-plan` 브랜치에서 시작합니다.
3. **내 파일만**: 지시서의 "저장 위치"에 적힌 파일만 만들거나 고칩니다. 다른 파일은 건드리지 않습니다. 고쳐야 할 게 보이면 `life/docs/REQUESTS.md` 맨 아래에 `- [GPT→Claude] 내용` 형식으로 적습니다.
4. **규격**: 조건·효과 키, 능력치·성향 축 이름은 `SPEC.md`에 있는 것만 씁니다. 새 키가 꼭 필요하면 쓰지 말고 REQUESTS.md에 요청합니다.
5. **검사**: 데이터 작업은 커밋 전에 `node life/tools/validate.mjs`를 돌려 오류 0개를 만듭니다.
6. **문장**: 문장 작업은 `life/docs/WRITING_GUIDE.md`를 먼저 읽고 따릅니다. 해요체, 짧고 장면이 보이게, 교훈조 금지, 그 직업이어야 겪는 일.
7. **금지**: 실제 회사 이름(패러디 이름만), 알아볼 수 있는 회사에 사고·비리 같은 부정적 사건 고정, 회사 내부 정보(실제 공정 조건·수율 수치), 전쟁·죽음·해고를 가볍게 다루기.
8. **마무리**: 커밋 → 푸시 → PR. PR 설명에 무엇을 / 왜 / 건드린 파일 / 확인 방법(검사 결과)을 적고, `CHANGELOG.md`의 `## 작업 중` 아래에 `- [GPT] ...` 한 줄을 추가합니다. 머지는 오너가 합니다.
